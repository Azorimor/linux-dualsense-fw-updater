4. Optional Local AppImage Builds (Not Distributed on GitHub Releases)
---------------------------------------------------------------------------
Official GitHub Releases do not publish prebuilt AppImage artifacts. If you
clone this repository and build a local AppImage yourself using
`scripts/package-appimage.sh`:
- The local AppDir bundles dynamically linked Qt 6, KF6 Kirigami, and host
  system shared objects under `usr/lib/`, `usr/plugins/`, and `usr/qml/`, and
  records bundled `.so` paths in `usr/share/licenses/linux-dualsense-fw-updater/BUNDLED_LIBRARIES.txt`
  alongside Debian/Ubuntu `system-packages/*.copyright` files when available.
- Per LGPL-3.0 §4 and LGPL-2.1 §6, a locally built AppImage can be extracted
  via `--appimage-extract` to inspect, modify, or replace bundled `.so` files
  and launched via `./squashfs-root/AppRun`.
- Local AppImage tooling uses `linuxdeploy` & `linuxdeploy-plugin-qt` (MIT) and
  the AppImage Type-2 Runtime (`https://github.com/AppImage/type2-runtime`,
  combining `type2-runtime` [MIT], `musl` [MIT], `libfuse` [LGPL-2.1],
  `squashfuse` [BSD-2-Clause], `libzstd` [BSD-3-Clause / GPL-2.0], and `zlib`
  [Zlib]). If you redistribute a locally built AppImage to others, you are
  responsible for complying with all bundled library and runtime license terms.
